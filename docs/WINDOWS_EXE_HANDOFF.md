# VBSE 发票教学工具 Windows 安装版交接文档

## 任务目标

请在本仓库中新增一个**可安装的 Windows 桌面应用**，交付安装程序（例如 `VBSE-发票教学工具-Setup-x.y.z.exe`），而不只是能双击运行的便携 EXE。首版须离线可用，保留网页版的发票录入、计算、预览、历史记录、企业快速选择和打印/另存为 PDF 功能。用途始终是教学实训；票面和安装版界面应醒目标注“教学样票，不作为真实开票或报销凭证”。

本任务尚未开始实施。交接文档仅定义下一位 agent 的工作范围，不代表桌面版已经构建或验收。

## 仓库现状与选型

- 桌面界面的最短路径是仓库根目录的 `VBSE发票小程序（2.2版).html`：单文件 HTML/CSS/JS，具备桌面布局、企业选择、明细计算、票面预览、二维码、历史记录和 `window.print()`。历史与下一发票号分别使用 `localStorage` 键 `vbseInvoiceHistory`、`vbseInvoiceNextNumber`，历史最多保留 100 条。
- 微信小程序位于 `miniprogram/`。`miniprogram/utils/invoice.ts` 有可供核对的业务计算、校验与 23 家企业预设；`miniprogram/utils/storage.ts`、小程序页面及图片导出使用 `wx` API，不能直接在桌面浏览器运行。桌面版首期不要把 WXML/WXSS 或小程序 Canvas 导出逻辑原样搬入。
- 根目录 `package.json` 仅有小程序构建和测试脚本，尚无桌面打包依赖。`README.md` 介绍的是小程序，不是 Windows 桌面版。
- **建议采用 Electron + electron-builder（NSIS 安装程序）封装现有 HTML**。这能复用已有桌面页面和打印能力，首版无需服务端。若改选 Tauri，先证明当前页面、打印、中文字体和离线持久化在 Windows WebView2 下同样可用，并记录选择理由。
- 当前企业库是代码内的固定预设，手动输入企业信息可用，但“用户可随时维护企业库”尚不是已有功能。不要在首版说明里承诺后台管理或云同步。

## 实施边界与步骤

1. 新增独立的桌面入口（主进程、必要时预加载脚本），加载打包后的本地 HTML；不要改变微信小程序的构建与运行。开发命令、打包命令和产物目录写入 `package.json`，不提交大体积构建产物。
2. 打包只包含桌面运行所需文件；HTML 中如有外部资源，先改为随安装包提供，断网启动必须正常。设置中文应用名、图标、版本、Windows x64 安装目标；安装器应支持正常安装、启动、升级和卸载。图标如仓库没有合适资源，先用明确标记的临时资源并列为发布前待办，不伪称正式品牌素材。
3. 保留输入、预览、历史回填/清空、号码自增及打印行为。验证 Electron 的打印对话框确实能选择系统打印机或“Microsoft Print to PDF”；如有差异，再做最小适配。不要把小程序“保存图片”当成网页版现有能力，也不要将 PDF 打印误写成真实电子发票开具。
4. **明确持久化策略**：首版可继续使用封装页面的 `localStorage`，但必须验证关闭/重开及安装包升级后数据不丢失；更稳妥的方案是把历史与号码存入 `app.getPath('userData')` 下的应用数据文件，并通过窄作用域 IPC 暴露读写。若采用后者，设计异常数据恢复和原子写入，并明确数据迁移。不要默认浏览器中旧 HTML 的 `localStorage` 会自动进入桌面应用：跨浏览器/源数据迁移需另做导入方案或在说明中明确不支持。
5. 设置 `contextIsolation: true`、`nodeIntegration: false`；按所选加载方式配置沙箱与 CSP，拒绝非预期外链导航和新窗口。不要向页面暴露通用文件系统或任意命令执行能力。企业名称、税号、历史票据可能是敏感本地数据，不上传、不写入调试日志。
6. 更新 `README.md`，区分微信小程序和 Windows 安装版的启动、构建、数据位置、备份与卸载说明。卸载时默认保留用户数据，除非用户明确选择删除；安装器与文档行为保持一致。未签名安装包可能触发 Windows SmartScreen，需如实说明；正式分发应评估代码签名。

## 验收清单

- 在干净的 Windows 环境运行安装程序，完成安装，桌面/开始菜单入口能打开应用；断网下页面和二维码可正常显示，未出现开发者工具依赖。
- 输入一张含多行、不同税率的发票，核对金额、税额和价税合计；选择企业后名称/税号正确回填，手动输入仍可用。
- 生成发票后查看历史、回填、打印历史发票、清空历史；号码自增正确。关闭应用重开后历史与下一号码仍在；升级覆盖安装后再次检查。
- 打印预览布局与现有网页版基本一致，完整覆盖购销方、明细、合计、备注与教学用途提示；使用 Windows PDF 打印机能保存并打开 PDF，不能出现裁切或文字溢出。
- 运行 `npm run verify`，确认小程序构建和原有测试未受影响；补充桌面启动/安装/持久化的验证说明或可自动化的冒烟测试。记录测试所用 Windows 版本、安装包路径及结果。
- 打包前执行 `git status --short`，仅提交本任务相关文件；不要清理或覆盖仓库现有的未跟踪 `diagram/`、`video_work/`。

## 给下一位 agent 的执行指令

先阅读 `README.md`、本文件、网页版 HTML、`package.json` 和现有测试，再以 Electron 封装网页版作为首版实现。先做可运行的开发入口，再验证本地数据与打印，最后打出 NSIS 安装包并在 Windows 上实际安装测试。实现过程中保留微信小程序原有逻辑；任何业务规则差异以现有网页版行为和 `miniprogram/utils/invoice.ts` 的测试结果交叉核对。交付时给出安装包路径、构建命令、测试结果、已知限制与数据存储位置；没有实际验证的功能不要宣称已通过。
